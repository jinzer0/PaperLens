# PaperLens 제품 브리프 부록

이 부록은 PRD, UX, 구현 계획에서 다시 찾아보기 위한 참조 문서다. 공개 브리프의 핵심 포지셔닝은 빠른 AI Reader와 개인 연구 지식이 누적되는 AI Library이며, 둘은 `read -> evidence -> organize -> revisit -> compound` 루프로 연결된다.

## 상태 표기

- `[결정]`: 제품 브리프와 후속 문서에서 그대로 유지할 확정 방향.
- `[후보]`: 가능성이 높지만 세부 설계나 구현 방식이 아직 열린 항목.
- `[가정]`: 아직 검증되지 않았으나 현재 계획을 진행하기 위한 실무적 전제.
- `[미정]`: 추가 결정이 필요한 질문.
- `[제약]`: 구현, 라이선스, 표현, 범위에서 지켜야 할 조건.

## 첫 릴리스 범위

- `[결정]` 첫 공개 버전은 논문 추천과 개인 지식 그래프를 제외한 핵심 기능이 실제로 작동해야 한다.
- `[결정]` 포함 범위는 arXiv URL 가져오기, PDF URL 가져오기, 로컬 PDF 가져오기, PDF Reader, 문장 정렬 번역, 기본 및 사용자 정의 템플릿 기반 Markdown 논문 브리프 생성, 인라인 근거, 논문 근거 기반 QA, 라이브러리 폴더 정리, 논문 카드, 하이라이트, 노트, 읽기 이력, BYOK, Codex OAuth다.
- `[결정]` 첫 릴리스의 판단 기준은 논문 가져오기, 읽기, 번역, 근거 확인, 질문 답변, 정리, 재방문까지 처음부터 끝까지 이어지는 사용 흐름이다.
- `[결정]` AGPL-3.0은 오픈소스 라이선스 후보로 고려 중이며 확정되지 않았다.
- `[제약]` 개발 맥락은 개발자 1명이 agentic coding으로 첫 공개 버전을 만드는 것이다. 이 사실은 범위와 실행 현실을 설명하는 배경이며 사용자 혜택으로 포장하지 않는다.

## Reader

### 필수 경험

- `[결정]` Reader는 PDF 원문, 번역, AI 채팅이 함께 있는 화면이다.
- `[결정]` 논문 읽기 중 번역과 AI 질문을 즉시 사용할 수 있는 흐름을 우선한다.
- `[결정]` Reader의 번역 패널과 AI 채팅은 자동으로 읽기 맥락을 공유하지 않는다. 맥락 전달이 필요할 때는 별도 상호작용으로 설계해야 한다.
- `[결정]` 원문과 번역은 문장 단위로 1대1 대조한다.
- `[결정]` 어느 쪽 문장에 마우스를 올려도 대응 문장 쌍을 회색 배경으로 함께 강조한다.

### 성능과 준비 상태

- `[결정]` arXiv URL 제출 후 PDF 원문을 볼 수 있을 때까지 최대 30초를 목표로 한다.
- `[결정]` 30초 안에 준비되지 않은 번역, 브리프, 기타 AI 작업은 작업별 로딩 진행률을 표시한다.
- `[결정]` 실시간 준비 UX에서는 번역 결과를 가장 먼저 노출한다.
- `[제약]` Reader 준비가 느리면 사용자가 핵심 가치를 경험하기 전에 이탈할 수 있다. 느린 UI 반응은 핵심 실패 요인이다.

### 구현 메모

- `[결정]` 전체 PDF를 한 번에 번역하지 않고 페이지 단위 번역 태스크로 나눈다.
- `[결정]` 완료된 페이지부터 보여주며, 미번역 페이지에서는 PDF 원문을 즉시 표시하고 번역 패널은 로딩 상태로 둔다.
- `[결정]` 사용자가 다른 페이지로 이동해도 번역 작업 순서는 변경하지 않는다.
- `[결정]` 페이지별 번역은 독립 태스크로 두고 병렬 처리해 대기 시간을 줄인다.

## 정리본, 근거, 화면 이동

### 확정된 정리본과 근거 요구사항

- `[결정]` 논문을 라이브러리에 추가하면 구조화된 Markdown 정리본을 생성한다.
- `[결정]` 기본 정리본은 논문이 해결하려는 문제, 기존 방법론의 문제와 한계, 제안 방법론, 논문이 명시한 한계, AI가 분석한 가능성 있는 한계, 추가 최적화 가능성, 방법의 장점과 한계를 포함한다.
- `[결정]` 사용자는 자신의 목적에 맞는 정리본 템플릿을 정의해 자동 정리본을 생성할 수 있다.
- `[결정]` 정리본에서는 "논문에서 밝힌 한계점"과 "AI가 분석한 가능성 있는 한계점"을 명시적으로 분리한다.
- `[결정]` 정리본의 문장이나 주장에는 원문 근거로 돌아갈 수 있는 인라인 근거가 붙어야 한다.

### 근거 상호작용

- `[결정]` 근거 위에 마우스를 올리면 짧은 원문 미리보기를 표시한다.
- `[결정]` 근거를 클릭하면 PDF의 정확한 문장 위치로 이동한다.

### 화면 간 이동

- `[결정]` 자동 정리본만 독립적으로 읽는 전용 화면을 제공한다.
- `[결정]` PDF Reader에서는 정리본을 PDF 위에 임시로 겹쳐지는 Drawer로 연다.
- `[결정]` Reader의 Drawer는 현재 PDF 페이지를 유지한 채 Markdown 정리본과 근거 인용을 보여준다.

## Library

- `[결정]` 라이브러리는 논문 정리와 읽기 히스토리를 통합 관리한다.
- `[결정]` 논문 카드에는 제목과 발행연도를 항상 표시한다.
- `[결정]` 한 줄 요약, Abstract 일부, 주제 태그는 마우스를 올렸을 때만 표시한다.
- `[결정]` 라이브러리에서 논문 카드를 클릭하면 PDF Reader로 이동한다.
- `[후보]` 라이브러리 첫 화면에는 최근 읽은 논문을 보여준다.
- `[후보]` 논문 목록에 한 줄 요약을 표시해 사용자가 논문 내용을 빠르게 회상하게 한다.

## EasyPaper 참조 제약

### 참고할 패턴

- `[후보]` EasyPaper는 번역, 문장 1대1 대조, 스크롤 매칭 등 Reader UX의 핵심 레퍼런스다.
- `[후보]` 참고할 패턴은 원문 PDF, AI 번역, 채팅, 라이브러리, 그래프, 읽기 기록, 추천의 통합이다.
- `[후보]` 세부 패턴은 문장 태그, 페이지별 스트리밍 번역, 번역과 PDF 사이의 양방향 hover 강조, 페이지 높이 동기화, 연속 스크롤, lazy rendering이다.

### 라이선스 제약

- `[제약]` EasyPaper 저장소에는 명시적 LICENSE 파일이 없으므로 코드 재사용 권한을 전제로 삼을 수 없다.
- `[제약]` EasyPaper는 UX 영감으로만 사용하고 구현은 독립적으로 해야 한다.

### 기술적 불확실성

- `[제약]` 문장 수가 맞지 않을 때 원문-번역 정렬이 흔들릴 수 있다.
- `[미정]` EasyPaper의 명시적 shared-scrollTop 동기화는 확인되지 않았다.
- `[후보]` 직접 매핑 실패 시 위치 비례 휴리스틱 같은 fallback은 참고할 수 있다.
- `[제약]` fallback이나 정렬 보정은 정확도 보장으로 표현해서는 안 된다.

## 후속 비전

- `[결정]` 개인 지식 그래프는 첫 릴리스 이후 범위다.
- `[후보]` 장기적으로는 태그와 정리 요약본의 관계를 이용해 사용자가 읽은 분야와 논문 관계를 탐색하게 하는 인터랙티브 그래프 GUI를 제공한다.
- `[결정]` 논문 추천도 첫 릴리스 이후 범위다.
- `[후보]` 장기적으로는 라이브러리 논문을 바탕으로 최신 논문과 관련 논문을 추천한다.
- `[후보]` 그 밖의 이후 아이디어는 연구 관계 그래프, AI 채팅 내용을 연구 기록으로 정리, 읽기 전 브리핑에 핵심 개요와 연구 계보, 파인만식 설명, 용어집, 질문 거리 제공, 인용과 그림, 표, 수식 참조를 읽는 위치에서 오버레이로 표시, 일반 목적 독립 AI 채팅과 논문 근거 기반 질문 답변 병행, QA 이후 후속 질문 추천이다.

## 미해결 결정

- `[미정]` Reader의 AI 채팅이 현재 페이지, 선택 문장, 하이라이트 같은 맥락을 수동으로 받는 방식은 추가 설계가 필요하다.

## 범위 결정

- `[결정]` 장기적으로는 기존 기획의 주요 기능을 대부분 포함하고 싶다는 방향을 유지한다.
- `[결정]` 동시에 첫 공개 릴리스는 완성 가능한 범위로 제한한다.
- `[결정]` 이 긴장은 첫 릴리스와 이후 비전을 명확히 분리해 해결한다. 첫 릴리스에는 추천과 지식 그래프를 넣지 않고, 나머지 핵심 읽기-근거-정리-재방문 루프를 실제 사용 가능하게 만든다.

## 성공 가정

- `[결정]` 초기 성공 기준은 실제 사용 가능한 오픈소스 공개 자체다.
- `[결정]` 정량 성공 기준은 아직 두지 않는다.
- `[가정]` 공개 후 제품 건강 신호를 본다면 가져오기부터 Reader 진입, 정리본 생성, 근거 확인, 라이브러리 재방문까지의 루프 완료와 반복 사용 여부가 실용적인 후보가 될 수 있다.
