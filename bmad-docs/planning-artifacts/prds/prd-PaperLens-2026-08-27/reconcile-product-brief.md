# 제품 브리프 대 PRD 조정 보고서

## 입력

## 판정

제품 브리프의 핵심 결정은 대부분 PRD 본문이나 부록에 반영되어 있다. Reader와 Library를 잇는 v1 제품 약속, `read -> evidence -> organize -> revisit -> compound` 루프, 원문 근거 기반 QA, Markdown 정리본, Library 재방문, 추천과 개인 지식 그래프의 v1 제외는 PRD에 명확히 들어갔다.

다만 브리프가 담고 있던 공개 소개 제품으로서의 이야기, 오픈소스 커뮤니티 초대 방식, 빠른 진입의 감성적 중요성은 PRD에서 요구사항과 제약으로 바뀌며 일부 약해졌다. 이 항목들은 기능 누락이라기보다 제품 서사의 결이 희석된 부분이다.

## 중요한 갭

### G-1. 오픈소스 커뮤니티 초대 문맥이 PRD 본문에서 약하다

브리프는 PaperLens를 잠재 사용자와 오픈소스 커뮤니티를 위한 공개 소개 제품으로 규정하고, 커뮤니티가 읽기 UX, 근거 연결, AI 연결 방식, 연구 정리 흐름을 함께 개선할 수 있다고 말한다. PRD 본문은 오픈소스 공개 상태를 성공 판단으로 둔다. PRD 11장 성공 판단은 "실제 사용 가능한 오픈소스 공개 상태"를 말하고, PRD 10장은 AGPL-3.0이 후보라고 제한한다. 부록 7장은 커뮤니티 개선 가능 영역을 보존한다.

갭은 PRD 본문 안에서 공개 대상과 커뮤니티 참여 포인트가 제품 포지셔닝이나 성공 판단으로 충분히 보이지 않는다는 점이다. 부록에는 보존되어 있으므로 요구사항 누락은 아니지만, 브리프의 공개와 오픈소스 방향 섹션이 가진 제품 서사는 본문에서 약하다.

관련 위치: 브리프 `공개와 오픈소스 방향`, PRD 10장, PRD 11장, 부록 7장.

권장 처리: 본문에 넣는다면 PRD 11장이나 10장에 "커뮤니티가 개선에 참여할 수 있는 공개 제품"이라는 한 문장 수준으로 충분하다. 넣지 않는 선택도 가능하며, 현재 부록 7장에 의도적으로 이동된 상태로 볼 수 있다.

### G-2. "빠른 진입"의 사용자 이탈 위험은 요구사항으로 쪼개졌지만 제품 스토리의 압박감은 줄었다

브리프는 사용자가 논문을 추가한 뒤 Reader에서 원문을 보기까지 오래 기다리면 핵심 가치를 경험하기 전에 이탈할 수 있다고 말한다. PRD는 이 결정을 제품 원칙, 상태 요구사항, 성능 NFR로 반영했다. PRD 3장은 빠른 진입을 원칙으로 두고, FR-016은 가져오기 완료 뒤 Reader 진입과 후속 AI 작업 준비 상태 표시를 요구한다. FR-090부터 FR-095는 비동기 작업 상태와 재시도, 일부 실패 시 원본 PDF 접근 유지를 정의한다. NFR-001부터 NFR-004는 30초 PDF-visible 목표와 AI 작업 분리를 둔다.

갭은 브리프의 "핵심 가치를 경험하기 전 이탈"이라는 제품 리스크 언어가 PRD 본문에서는 기능과 NFR로만 표현된다는 점이다. PRD 12장 리스크에는 PDF 파싱, Provider onboarding, 기능 밀도 리스크는 있지만 느린 Reader 진입 자체가 사용자 가치 상실로 이어진다는 리스크 문장은 없다.

관련 위치: 브리프 `첫 공개 릴리스 범위`, PRD 3장, FR-016, FR-090부터 FR-095, NFR-001부터 NFR-004, PRD 12장.

권장 처리: PRD 12장에 느린 Reader 진입이 첫 가치 경험 전 이탈을 만든다는 리스크를 추가하면 브리프의 제품 판단이 더 온전히 잡힌다.

### G-3. "이해도를 채점하지 않는다"는 사용자 가치 경계가 직접 반영되지 않았다

브리프는 PaperLens가 이해도를 채점하지 않고, 사용자가 핵심을 빠르게 파악하고 근거를 확인하며 자신의 연구 지식으로 보존하도록 돕는다고 설명한다. PRD는 이 중 빠른 파악, 근거 확인, 보존을 JTBD와 기능 요구사항으로 반영했다. PRD 2장의 JTBD, FR-041부터 FR-042의 근거 기반 답변, FR-053부터 FR-061의 정리본, FR-075부터 FR-088의 Library 기록이 여기에 해당한다.

갭은 "이해도 채점" 또는 학습 평가 제품이 아니라는 경계가 PRD 비목표나 제약에 명시되지 않았다는 점이다. 현재 PRD 4.2의 비목표에는 추천, 지식 그래프, 로컬 모델, 클라우드, OCR 등이 있지만 학습 퀴즈, 이해도 평가, 시험형 기능 제외는 없다.

관련 위치: 브리프 `누구를 위한 제품인가`, PRD 2장, PRD 4.2, FR-041부터 FR-042, FR-053부터 FR-061, FR-075부터 FR-088.

권장 처리: 사용자가 PaperLens를 학습 평가 도구로 오해할 가능성을 줄이려면 PRD 4.2에 "이해도 채점이나 학습 평가 기능"을 v1 비목표로 추가할 수 있다.

### G-4. 브리프의 v1 범위보다 PRD가 더 넓어졌고 일부는 브리프에 없는 새 결정이다

브리프의 v1 범위는 가져오기, Reader, 정리본, 근거 연결, Library, AI 연결이다. PRD는 이를 유지하면서 첫 실행 provider 설정과 연결 테스트, macOS only, 로컬 앱 데이터, 삭제 semantics, 검색/필터, 중복 경고, Paper Chat 세션 관리, 정리본 독립 화면과 Reader Drawer, 작업 실패 복구를 더 구체화했다. 대표 요구사항은 FR-001부터 FR-009, FR-015, FR-043부터 FR-050, FR-066부터 FR-068, FR-087부터 FR-088, FR-090부터 FR-101이다.

이 확장은 브리프와 충돌하지 않으며 newer PRD decision으로 볼 수 있다. 다만 v1 범위가 커졌기 때문에 PRD 12장의 R-007처럼 1인 개발 일정과 품질 리스크가 생긴다. 브리프의 "추천 시스템과 개인 지식 그래프를 제외한 핵심 기능"보다 PRD의 실제 완료 조건은 더 촘촘하다.

관련 위치: 브리프 `첫 공개 릴리스 범위`, PRD 4.1, FR-001부터 FR-101, PRD 12장 R-007.

권장 처리: 갭이라기보다 범위 확장 확인 항목이다. 확장을 유지한다면 PRD 12장의 R-007로 충분히 경고되어 있다. 축소가 필요하면 PRD의 열린 질문이나 MVP 컷 논의에서 다룰 수 있다.

### G-5. AI 연결 표현은 의도적으로 supersede 되었지만 브리프 수준의 BYOK 단순성은 줄었다

브리프는 AI 연결을 BYOK와 Codex OAuth로 간단히 설명한다. PRD는 이를 OpenAI API key와 공식 Codex SDK의 ChatGPT 로그인 또는 device-code 흐름으로 바꿨고, generic Codex OAuth provider 계약을 지원하지 않는다고 명시했다. FR-004부터 FR-006, PRD 10장 제약, 부록 1장과 5장이 이 supersede를 분명히 한다.

갭은 아니다. 다만 브리프가 의도한 사용자 언어의 "자기 키를 가져오거나 OAuth로 연결"이라는 단순한 가치 설명은 PRD의 기술 계약 표현으로 바뀌었다. 제품 소개 문서에서는 다시 쉬운 표현으로 풀 필요가 있다.

관련 위치: 브리프 `첫 공개 릴리스 범위`, FR-004부터 FR-006, PRD 10장, 부록 1장, 부록 5장.

권장 처리: PRD 기준으로는 supersede 완료. 후속 공개 소개 문서에서만 사용자 친화 표현을 복원하면 된다.

## Superseded 또는 의도적으로 이동된 항목

- `Codex OAuth`라는 브리프 표현은 PRD에서 공식 Codex SDK의 ChatGPT 로그인 또는 device-code 흐름으로 supersede되었다. 관련 요구사항은 FR-004부터 FR-006이며, 부록 1장과 5장에도 충돌 처리로 남아 있다.
- 브리프보다 구체적인 macOS only, 로컬 앱 데이터, no cloud sync, no mobile 범위는 PRD 4.1, 4.2, 8장, NFR-009부터 NFR-012에 추가된 newer PRD decision이다.
- 추천과 개인 지식 그래프는 PRD 4.2에서 v1 비목표로 두고, PRD 14장과 부록 8장에 이후 비전으로 이동했다.
- 오픈소스 라이선스는 PRD 10장과 13장에서 미정으로 남겼고, 부록 7장에 맥락을 보존했다.
- 구체 구현 방식과 기술 선택은 PRD 본문 밖으로 빼고 부록과 Architecture 단계로 이동했다. PRD 10장과 부록 3장부터 6장, 9장이 이 경계를 잡는다.

## 최종 요약

PRD는 제품 브리프의 기능적 핵심을 거의 모두 포착한다. 가장 큰 남은 차이는 기능 요구사항이 아니라 제품 언어의 온도다. 공개 오픈소스 제품으로서 누구를 초대하고 무엇을 함께 개선할지, 사용자가 첫 가치를 보기 전에 기다리다 떠나는 위험, 이해도 평가 도구가 아니라 읽기와 근거 확인과 보존을 돕는 도구라는 경계가 PRD 본문에서 더 분명해지면 브리프의 의도가 더 온전히 이어진다.
