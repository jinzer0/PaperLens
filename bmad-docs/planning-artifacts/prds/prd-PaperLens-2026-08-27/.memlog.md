- (event) PaperLens 제품 브리프와 부록을 입력으로 새 PRD Create 흐름을 시작한다
- (decision) 추천과 지식 그래프를 제외한 가져오기, Reader, 문장 대조 번역, 근거 기반 QA, 정리본, 커스텀 템플릿, Library, 하이라이트, 노트, 읽기 이력, BYOK, Codex OAuth를 모두 첫 출시 필수 범위로 확정한다
- (decision) PaperLens는 local-first를 제품 원칙으로 적용하지 않으며 AI 기능 사용을 위해 논문 및 개인 데이터를 외부 provider로 전송할 수 있다
- (decision) 사용자는 PaperLens 사용 시 외부 AI provider로의 데이터 전송을 전제로 받아들여야 한다
- (decision) 외부 provider 연결에 별도의 필수 동의 절차나 데이터 전송 고지를 두지 않는다
- (decision) 프라이버시가 필요한 사용자는 로컬 모델을 선택하고 외부 전송을 허용하는 사용자는 외부 provider를 선택하는 모델 선택 책임을 가진다
- (decision) Ollama 등 로컬 모델 연결은 첫 출시 범위에서 제외하고 후속 기능으로 둔다
- (decision) 첫 출시의 AI 기능은 BYOK 또는 Codex OAuth로 연결한 외부 provider를 전제로 한다
- (decision) 첫 실행 시 AI Provider 설정을 필수 onboarding으로 강제한다
- (decision) 사용자는 provider 연결과 연결 테스트를 성공해야 PaperLens의 전체 기능을 사용할 수 있다
- (decision) AI Provider를 연결하지 않은 상태에서 Reader나 Library만 사용하는 제한 모드는 제공하지 않는다
- (decision) 첫 출시에서 지원하는 AI 연결 방식은 OpenAI API key와 Codex OAuth 두 가지로 제한한다
- (decision) UJ-1 대표 사용자는 연구자 김철수이며 논문 PDF 링크를 PaperLens에 입력하고 준비된 논문을 Reader에서 읽는다
- (decision) UJ-1에서 김철수는 Reader의 번역, 논문 QA, AI Chat을 사용한 뒤 메인 화면으로 돌아간다
- (decision) UJ-1에서 김철수는 사이드바의 Library 또는 정리본 탭에서 논문 요약 정리본을 별도로 확인하고 논문을 원하는 폴더로 이동한다
- (assumption) 공식 조사 결과 generic Codex OAuth provider contract는 확인되지 않았고 공개 Codex SDK의 ChatGPT sign-in/device-code flow만 지원 가능한 계약으로 보인다
- (event) Codex SDK의 chatgptAuthTokens protocol mode는 internal-only이므로 사용하지 않아야 한다
- (override) 첫 출시의 Codex OAuth 요구사항을 공식 Codex SDK ChatGPT 로그인 또는 device-code 흐름 지원으로 변경한다; generic OAuth 계약이 공식적으로 확인되지 않았기 때문이다
- (decision) Reader에서는 Paper QA와 일반 AI Chat을 분리하지 않고 하나의 Chat으로 제공한다
- (decision) 통합 Chat은 논문 근거 QA가 항상 활성화되며 사용자가 모드를 켜거나 끄는 UI는 제공하지 않는다
- (decision) Paper Chat 대화 기록은 논문별로 자동 저장하고 앱 재실행 후 이어서 질문할 수 있게 한다
- (decision) 한 논문은 여러 Paper Chat 세션을 가질 수 있다
- (decision) 사용자는 논문 안에서 새 Paper Chat 세션을 시작할 수 있다
- (decision) 사용자는 저장된 이전 Paper Chat 세션 목록에서 필요한 세션을 불러와 대화를 계속할 수 있다
- (decision) Paper Chat 세션 제목은 첫 질문을 바탕으로 자동 생성한다
- (decision) 사용자는 Paper Chat 세션 제목을 수정할 수 있다
- (decision) 사용자는 Paper Chat 세션을 삭제할 수 있다
- (decision) PDF 파싱 실패 시 원본 Reader는 계속 제공한다
- (decision) 파싱 실패 시 번역, Paper Chat, 자동 정리본을 비활성화하고 오류 정보와 재시도 기능을 제공한다
- (decision) 구체적인 PDF 파싱 기술과 라이브러리 선택은 PRD가 아니라 후속 Architecture 단계에서 결정한다
- (decision) PRD는 Fast path로 진행해 남은 공백을 한두 번에 확인한 뒤 전체 초안을 작성한다
- (event) Party Mode에서 제품, UX, 아키텍처, 구현 관점의 discovery를 완료했다
- (decision) 첫 출시 지원 운영체제는 macOS로 제한한다
- (decision) 논문, 번역, 정리본, Paper Chat, 하이라이트, 노트, 읽기 이력은 로컬 앱 데이터에 저장하고 계정과 클라우드 동기화는 제공하지 않는다
- (decision) 논문 삭제 시 PDF 파일과 연결된 번역, 정리본, Paper Chat 세션, 하이라이트, 노트, 읽기 이력을 모두 삭제한다
- (decision) OpenAI API key 등 provider 비밀정보를 OS keychain에 저장하지 않는다
- (decision) 번역 대상 언어는 설정에서 변경할 수 있으며 기본값은 한국어다
- (decision) 사용자 정의 정리본 템플릿에서 Markdown 항목과 프롬프트를 직접 편집할 수 있다
- (decision) Reviewer의 v1 범위 축소 권고는 수용하지 않고 모든 확정 핵심 기능을 출시 필수로 유지하며 범위 리스크를 명시한다
- (decision) 초기 기획에 포함된 즐겨찾기를 v1 Library 필수 기능으로 확정한다
- (decision) Paper Chat은 현재 페이지나 선택 문장과 자동 또는 수동 맥락 공유를 요구하지 않고 논문 전체 검색 근거로 답변한다
- (decision) 성공 판단은 사용자 성장 지표가 아니라 v1 end-to-end 출시 acceptance gate로 정의한다
- (assumption) 근거 앵커는 PDF 페이지, 추출 문장 식별자, 화면에서 보이는 강조 위치로 검증하며 UX/Architecture에서 세부 계약을 확정한다
- (event) AGPL-3.0 최종 확정은 출시 전 라이선스 결정 시점까지 defer한다
- (event) A-001 Evidence Anchor 세부 계약은 UX/Architecture 시작 시 확정하고 그 전까지 페이지+문장 식별자+visible highlight 가정을 사용한다
- (event) A-002 30초 PDF-visible 검증 조건은 Architecture/QA 계획에서 테스트 corpus와 네트워크 조건을 정할 때 확정한다
- (event) A-003 keychain 미사용 secret 저장 경계는 Architecture 시작 전 보안 결정으로 확정한다
- (event) O-001 AGPL-3.0 최종 선택은 공개 배포 패키징 전에 결정하며 PRD/UX/Architecture 진행을 막지 않는다
- (event) 최종 PRD reviewer gate를 통과했다: overall adequate, critical 0, high 0
- (change) Structure/prose polish에서 traceability 구조는 유지하고 중복 표현, 판단형 acceptance 문구, public v1 라이선스 표현을 정리했다
- (event) PRD finalized

- (decision) PaperLens 공개 저장소와 v1 공개 패키지의 최종 라이선스로 AGPL-3.0-only를 채택한다
